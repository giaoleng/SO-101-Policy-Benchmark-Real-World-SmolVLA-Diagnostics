# 模块 2：相机标定与视角固定

## 先区分两种“相机标定”

本项目当前 SmolVLA 主要消费 RGB 图像。对这种图像策略，部署必需的是**相机身份、安装位置、视野、分辨率、帧率和图像特征名稳定一致**；并不因为有两路相机就必须先求出相机内参和相机到机器人基座的外参矩阵。

只有当后续算法使用相机测量三维位置、深度、PnP 或 camera-to-base 坐标变换时，才需要进一步进行几何标定（内参、畸变参数和外参）。不要把可选的几何标定误写成当前 SmolVLA RGB 推理的硬性前置条件。

## 1. 识别相机

在真机环境执行：

~~~bash
lerobot-find-cameras
~~~

记录每台相机的设备 ID、OpenCV index、默认分辨率和帧率。可以逐个拔插 USB 并重新扫描，确认哪个设备是全局/前视相机、哪个设备是腕部相机。不要仅凭 index 0 / 1 猜测相机身份；重启、USB 端口变化或新增设备都可能改变枚举顺序。

## 2. 固定安装位置和采集条件

- Front 相机：固定在工作区外部，完整覆盖方块、杯子、机械臂抓取区域和放置区域。
- Wrist 相机：固定在腕部刚性支架上，抓取时能看到夹爪、目标方块和接触区域；运动时线缆不能拉扯或进入关节夹缝。
- 固定支架、俯仰角、焦距/焦点和相机朝向；每组训练数据和正式评测期间不要随意移动。
- 核对曝光、白平衡、对焦和照明是否会自动大幅变化。条件允许时锁定自动曝光/白平衡，避免同一场景的图像分布漂移。
- 本项目参考配置目标为 640×480、30 FPS；实际支持情况以相机检测结果为准，并保证采集、训练和推理一致。

将相机设备索引和图像设置写入 <code>configs/real/so101.yaml</code> 的 <code>robot.cameras.front</code> 与 <code>robot.cameras.wrist</code>。这里的 front / wrist 是本机硬件相机名称，不等于训练数据集中的 feature key。

## 3. 核对数据集 feature 映射

本项目参考数据集使用：

- <code>observation.images.front</code>（历史数据中的 <code>observation.images.overhead</code> 兼容映射至同一模型输入）
- <code>observation.images.wrist</code>

本项目本机采集配置使用 front / wrist 时，必须在训练和评测配置中显式映射并保持一致。检查以下内容：

1. 训练集 meta/info.json 中实际图像 feature 名称和图像尺寸。
2. checkpoint config.json 中声明的视觉输入 feature。
3. 真机配置中 front / wrist 对应的物理相机。
4. 评测时传入的 rename_map 是否把同一物理视角映射到训练时相同的模型输入。

不要因为两个相机的分辨率相同，就把腕部视角和全局视角互换。

## 4. 何时做几何内外参标定

如果后续需要从图像计算三维位置或把相机坐标变换到机器人基座坐标：

1. 使用固定棋盘格或 AprilTag 标定板，采集覆盖不同距离、角度和画面位置的多张图像。
2. 计算每台相机的内参矩阵和畸变参数，并保存标定工具、图像尺寸和日期。
3. 若需要 camera-to-base 变换，使用固定在工作区中的已知标记/标定板和机器人基座坐标系，按所用工具的手眼/外参流程求解。
4. 使用未参与求解的图像或已知空间点验证重投影误差和坐标变换误差。
5. 相机移动、镜头焦距变化、分辨率裁剪变化或支架重新安装后，重新验证，必要时重做标定。

不要直接复制其他开源仓库作者的相机矩阵或 AprilTag 外参；它们只适用于作者自己的相机、镜头、安装位置和机器人坐标系。

## 5. 参考图像与本地参数

- <code>calibration/camera/reference/</code>：放置棋盘格/AprilTag 参考照片、视角检查照片和说明性图片。
- 实际设备的内参/外参文件应在本机单独保存，并记录相机序列号、分辨率、标定日期和工具版本。
- 本仓库只跟踪说明文件和 reference 占位文件，不提交设备专属的相机参数。
